# 單一專案邀請連結

## 權限規則

- 工作區 owner／admin 可在專案右上角「分享專案」建立邀請連結，個人與共享工作區的專案皆支援。editor／viewer 不能建立、管理或撤銷連結。
- 連結可設定「僅檢視」或「可編輯」，加入期限可選 1 天、7 天、30 天或 1 年。
- **期限只限制接受邀請**。到期後不能新加入；已接受的人保留專案權限，直到連結撤銷。不需要到期排程服務。
- 對方必須登入已驗證 Email 的帳號，查看專案名稱與角色，再按「接受邀請」。只預覽不授權、不會建立工作區成員資格。
- 受邀者在工作區頁的「受邀專案」看到專案，不能查看來源工作區的其他專案、成員名單、邀請或管理功能。
- 可編輯者可修改畫布、上傳附件及使用自己的 Gemini Key；僅檢視者可閱讀、匯出與下載，不能修改畫布或上傳。專案更名／刪除、分享與備份管理仍需原工作區權限。
- 變更連結角色會套用到已加入的人。撤銷連結會收回經該連結取得的權限，同時更新 Liveblocks 房間 ACL。
- 權限取聯集：同一人若有其他有效連結或原本的工作區成員資格，會保留那些權限。移除工作區成員也不會自動撤銷獨立的專案邀請授權。

## 使用

1. owner／admin 開啟專案 →「分享專案」→ 選角色、加入期限 →「建立邀請連結」。
2. 複製新連結並自行交給對方。原始連結只顯示一次；重新載入後無法重建相同網址，需要重新建立。
3. 對方開啟連結 → 登入／註冊並完成 Email 驗證 → 回到原邀請分頁登入 →「接受邀請」。
4. 之後可由「受邀專案」再開啟，不需保留原邀請網址。
5. 管理者可在同一視窗調整角色或撤銷。已到期但未撤銷的連結仍可調整既有協作者權限。

每個專案最多保留 20 條未撤銷連結。任何取得未到期連結的人，都可用自己的帳號接受；這不是指定 Email 的邀請。不要將連結放在公開貼文或問題截圖中。若誤傳，撤銷並建立新連結。

## 安全與同步

連結使用 32 bytes 隨機 token，Neon 只保存 SHA-256 雜湊。網址將 token 放在 fragment（`#` 後），不放在請求路徑或 query；接受頁移除網址 fragment，暫存在該分頁的 sessionStorage，透過 POST body 送給 Backend。完成、取消或確認連結無效後清除。邀請頁不索引，使用 `no-referrer`。

所有專案資料入口都以工作區角色與獨立專案授權檢查，包括畫布讀寫、AI、檔案上傳／完成／下載、Liveblocks 授權。工作區列表與管理 API 不接受專案授權。連結接受、角色變更與撤銷沿用跨實例 advisory lock；先收回雲端權限、Neon 成功後才授予新權限，避免提交失敗卻先開放存取。

畫布每 15 秒及回到分頁時重新確認角色，撤權後移除畫布並提供返回入口；雲端 ACL 和 Backend 權限檢查不依賴這個前端輪詢。已下載的內容無法收回。已發出的附件下載預簽網址最長 180 秒仍可能有效；撤權後不能取得新的下載網址，也不能完成上傳。

## 部署

新增 migration `0005_project_invite_links.sql`，只建立 `project_invite_links`、`project_invite_grants` 及索引／外鍵，不重寫既有資料。不要修改已套用的 migration 或 ledger。

1. 部署前後端新版，先維持 `PROJECT_INVITES_ENABLED=false` 或未設定；此時 Backend 不讀新資料表，原有功能可繼續使用。
2. 在 Neon 對目前 production 分支建立新的備份分支。**原本 production `DATABASE_URL` 不變，不改成備份或測試分支。**
3. 確認本機 Backend 指向預期的 production 目標且有備份，再執行：

   ```sh
   pnpm --filter @context-flow/backend db:migrate
   ```

   只會套用 ledger 尚未記錄的 migration。若已套用版本的 hash 與檔案不同，依 [Neon 指南](02-neon-database.md) 核對，不重跑或覆寫。
4. Vercel **Backend / Production** 新增 `PROJECT_INVITES_ENABLED=true`，重新部署。Frontend 不需要新變數，不需要新增 Liveblocks／R2／Inngest 服務。
5. 用測試專案與非工作區成員帳號驗收檢視、編輯、到期與撤銷。確認 Liveblocks 真實房間 ACL 已收回，不能只看前端按鈕。

若要停用此功能，先在仍啟用時撤銷所有尚有效的邀請連結，確認房間 ACL 已收權，再停用旗標。直接關閉旗標不能代替已發出雲端權限的撤銷，也不要刪除資料表作為回退。

刪除專案仍僅限工作區擁有者／管理員，受邀編輯者不能操作。刪除會移除該專案的連結及加入授權；原始附件若啟用清理，另依 [R2 寬限期規則](03-cloudflare-r2.md#刪除專案後清理原始檔) 處理，與單純撤銷邀請不同。

## 測試

```sh
pnpm test
pnpm test:e2e:api
pnpm exec playwright test e2e/project-invites.spec.ts e2e/collaboration.spec.ts
pnpm test:db
```

API 測試檢查登入與明確接受、只存雜湊、重複接受、專案隔離、期限、聯集權限、角色調整、撤銷、停權、檔案授權及資料庫失敗不先授權。Liveblocks／R2 使用替身。

瀏覽器測試走分享視窗、登入導回、接受失敗重試、受邀清單、檢視與編輯切換、正在開啟中的撤權與無效連結。Neon 測試只使用通過隔離檢查的 `TEST_DATABASE_URL`，驗證 migration、重新載入後的獨立授權、角色變更與撤銷，不改 production 連線設定。
