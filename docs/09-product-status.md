# ContextFlow 功能盤點與開發狀態

> 本文件依目前 repository 的實際程式碼整理，規格書中尚未接線的功能會列在「尚未完成」而不是當成既有功能。

## 1. 產品定位

ContextFlow 是以專案脈絡為中心的工作區。使用者可以在同一個專案中管理資料、和 AI 對話，將 AI 回覆轉成 React Flow 節點，再透過發散思考與收斂總結整理成可追蹤的思考圖。

目前產品主流程是：

```text
註冊／登入 → 工作區 → 專案 → 資料池 → AI 對話 → 發散節點 → 收斂總結
```

## 2. 已完成的功能

### 2.1 帳號與安全

- 使用者註冊、登入、登出。
- Access JWT 與 HttpOnly Refresh Cookie。
- Refresh token rotation 與登出全部裝置。
- 密碼雜湊使用 Node.js scrypt。
- 基本帳號設定、顯示名稱與密碼變更頁面。
- 使用者可自行設定、測試、更換、刪除 Gemini API Key。
- Gemini Key 由後端加密儲存，前端只看遮罩提示。

### 2.2 工作區與專案

- 註冊時自動建立個人工作區。
- 建立共享工作區。
- 共享工作區邀請、接受、拒絕成員。
- 成員角色：`owner`、`admin`、`editor`、`viewer`。
- 成員角色修改、移除成員與離開工作區。
- 建立專案、列出專案、查看專案。
- 個人工作區與共享工作區的基本權限檢查。
- 管理員可查看帳號、切換一般使用者／管理員角色、停權／啟用帳號。

### 2.3 專案畫布

- React Flow 三個區域：
  - 資料架構區（Data Zone）
  - 發散思考區（Divergence）
  - 收斂總結區（Convergence）
- 左右與上下兩種區域排列模式。
- 節點新增、編輯、刪除與拖曳。
- 文字、連結、圖片節點。
- Markdown/GFM 內容顯示。
- 節點雙擊編輯。
- 節點右上角重要標記（Star）。
- 節點之間手動建立連線。
- 連線文字編輯與刪除。
- 空白處點擊可回到全域對話；選取發散節點後可進入專屬對話。
- 發散節點的延伸回覆會以選定節點為來源繼續往下建立。
- 新增節點會嘗試放在目前畫布視窗中心。
- 各區清除畫布，並使用自訂二次確認彈窗。
- 自動排版：資料架構、發散與收斂各有對應的樹狀排版邏輯。
- 收斂結果會解析 Markdown 標題與列點，建立分層節點與不同層級顏色。
- 畫布按鈕、禁用狀態、載入狀態與自訂 Tooltip。

### 2.4 AI 工作流

- 一般對話只帶入目前節點脈絡（若有）與最近對話歷史，不使用 RAG，保留多方向與創意發散能力。
- 對話可重做、複製、編輯使用者訊息與開啟新對話。
- AI 回覆可轉成發散思考節點預覽，確認後才加入畫布。
- 專屬節點對話會限制在發散區節點脈絡。
- 收斂總結使用設計思考雙鑽石（Discover → Define → Develop → Deliver）提示。
- 收斂提示要求輸出多條可比較路線、收斂建議與下一步。
- 收斂區再次整理時，提示 AI 以增量修訂為主。
- AI 回覆與收斂結果均以 Markdown 呈現。

目前的 AI 策略決策：發散區先使用一般 LLM；收斂區先整理資料池與發散節點，未來需要來源追溯時，再為收斂流程加入真正的 RAG。這不是把資料池全文塞進每次發散對話，而是刻意保留發散階段的探索空間。

### 2.5 後端與基礎設施骨架

- NestJS API 模組與全域 JWT／角色 Guard。
- 記憶體模式的 `AppStore`，可在本機完成基本流程測試。
- Drizzle schema 與初始 migration。
- Cloudflare R2 預簽上傳 URL endpoint。
- Liveblocks 授權 endpoint 骨架。
- Inngest endpoint 與 client 骨架。
- API rate limiting（Throttler）。

## 3. 尚未完成或目前只有骨架

### 3.1 資料保存與多人共編

- `DATA_MODE=neon` 尚未完成 repository 接線；目前重啟 backend 後記憶體資料會消失。
- 三區節點／連線、資料池、一般／專屬對話歷史與收斂摘要文字目前已透過 canvas snapshot API 自動載入／儲存，但暫存於 memory store；backend 重啟後仍會消失。
- Liveblocks authorization endpoint 已有，但 React Flow 的 Presence、游標、節點與連線同步尚未完整接入畫布。
- Workspace audit log 目前存在記憶體結構，尚未完整落盤。

### 3.2 知識庫與 RAG

- 目前檔案上傳 API 只提供 R2 預簽 URL，尚未完成檔案清單、解析、切片與狀態追蹤 UI。
- 目前產品流程暫不啟用 RAG；發散思考區不會查詢或引用資料池。
- PDF、純文字、Markdown 的內容解析與 Embedding 尚未完成。
- Neon pgvector 相似度搜尋尚未接線。
- AI 回覆的 grounding source、檔案頁碼／行號溯源尚未完成。
- 圖片目前可作為節點預覽，尚未完成多模態 RAG。

### 3.3 畫布能力

- 節點群組／框選群組尚未完成：尚無群組資料模型、群組拖曳、群組底色與群組內節點管理。
- 尚未提供專案或畫布匯出為 PDF、Markdown、PNG、SVG、JSON。
- 尚未提供匯出時的版面整理、字型嵌入、分頁與高解析度輸出。
- 尚未提供專案複製、版本歷史、復原／重做與操作記錄。
- 影片節點（YouTube、Vimeo、MP4）、程式碼語法高亮與 Lightbox 尚未完成。
- 節點 Grounding source badge、標籤與篩選尚未完成。
- 收斂結果目前會新增節點；尚未完成穩定的「只微調既有節點」差異更新與去重策略。

### 3.4 使用體驗與文件

- 新手導覽、互動式教學與完整 onboarding 尚未完成。
- 尚未建立正式的元件文件、API reference、資料模型說明與貢獻指南。
- 尚未建立匯出、群組、權限與多人共編的端對端測試。
- 目前仍有部分 ESLint/Tailwind 格式建議，且應在 npm/pnpm 可用的環境重新執行完整 lint、typecheck、test 與 build。

## 4. 後續建議優先順序

1. 先將目前的畫布快照（三區 nodes、edges、對話、資料池、摘要）接到 Neon repository，讓保存跨 backend 重啟持續存在。
2. 再接入 Liveblocks，確保共享工作區的即時同步與權限一致。
3. 完成節點群組，包含群組底色、群組移動與群組內節點操作。
4. 設計統一匯出資料格式，再依序實作 Markdown、JSON、PNG/SVG、PDF。
5. 先觀察收斂是否需要可驗證來源；確認需求後，再補齊收斂專用的 RAG 解析、Embedding、搜尋與來源溯源。
6. 最後製作面向新手的教學文件、互動導覽與開源套件風格的 API／貢獻文件。
